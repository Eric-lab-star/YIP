  앞으로 **미사일·운석·HUD 클래스**까지 들어오면 이 파일은 수백 줄이 된다냥.

<Callout type="goal">

  - `from A import B` 문법을 읽고 쓸 수 있다.
  - **리팩토링**이 무엇인지 설명할 수 있다.

## 1단계 · 모듈과 패키지 (6분)

<Callout type="analogy">
  요리책으로 비유하면 이렇다냥.

  - **모듈** = 파스타 레시피 **페이지 한 장** (`.py` 파일 하나)
  - **패키지** = 이탈리안 요리책 **한 권** (모듈들을 담은 폴더)
</Callout>

우리는 이미 둘 다 써봤다냥.

```python
import pygame                      # pygame 이라는 패키지를 통째로
from os.path import join           # os 패키지 → path 모듈 → join 함수만
```

**직접 만든 파일도 똑같이 가져올 수 있다냥.** 그게 오늘 할 일이다냥.

## 3단계 · 폴더 구조와 import (8분)

우리가 만들 구조다냥.

```
space_shooter/
├── main.py           ← 게임 루프만 남는다
├── settings.py       ← 창 크기 같은 설정값
├── images/
└── entity/           ← 게임에 등장하는 것들 (패키지)
    ├── player.py
    └── bg.py
```

가져다 쓰는 쪽은 이렇게 쓴다냥.

```python
from settings import WINDOW_WIDTH, WINDOW_HEIGHT
from entity.player import Player
```

<Callout type="important">
  `from entity.player import Player` 를 뜯어보자냥.

  - `entity` → 폴더(패키지) 이름
  - `.player` → 그 안의 `player.py` 파일(모듈)
  - `import Player` → 그 파일 안의 `Player` 클래스

  **폴더는 점(`.`)으로 파고 들어간다냥.** 파일 확장자 `.py` 는 쓰지 않는다냥.
</Callout>

## 4단계 · 리팩토링이 뭐냥? (5분)

<Callout type="analogy">
  리팩토링은 **방 청소**다냥.
  물건을 버리거나 새로 사는 게 아니라, 어질러진 것을 **제자리에 정리**하는 것이다냥.
</Callout>

**동작은 하나도 안 바뀌고 구조만 좋아지는 모든 작업**이 리팩토링이다냥.

- 긴 함수를 작은 함수로 쪼개기
- 중복된 코드를 하나로 합치기
- 이름을 더 알아보기 쉽게 바꾸기
- **하나의 파일을 여러 모듈로 나누기** ← 오늘 할 일

<Callout type="tip">
  리팩토링의 핵심은 **"고치기 전과 후의 화면이 똑같아야 한다"** 는 것이다냥.
  오늘 실습이 끝나도 게임 화면은 지난 시간과 완전히 같다냥.
  달라지는 건 **파일이 몇 개인가** 뿐이다냥.
</Callout>

## 5단계 · 그리는 순서 (5분)

오늘 배경도 클래스로 만들 건데, 여기에 함정이 하나 있다냥.

```python
all_sprite_group.draw(display_surface)
```

이 한 줄이 그룹 안의 스프라이트를 **들어온 순서대로** 그린다냥.
나중에 그려진 게 위에 덮인다냥.

<Callout type="important">
  그래서 **배경을 먼저** 그룹에 넣어야 한다냥.

  ```python
  Background(all_sprite_group)   # 먼저 → 아래에 깔린다
  Player(all_sprite_group)       # 나중 → 위에 그려진다
  ```

  순서를 바꾸면 **배경이 우주선을 덮어버려서 우주선이 사라진다냥!**
</Callout>
