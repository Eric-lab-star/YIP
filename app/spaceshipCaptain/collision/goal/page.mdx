# 충돌 처리하기

<NyangSpeech>
  지금 미사일이 운석을 **그냥 뚫고 지나간다냥.**
  당연하다냥 — 화면에 그려진 그림일 뿐이지 진짜 물체가 아니니까냥.
  부딪혔는지는 **우리가 코드로 계산해서 알려줘야 한다냥.**
  오늘은 그 방법과, 그러기 위해 필요한 **그룹 나누기**를 배운다냥!
</NyangSpeech>

## 오늘의 학습 목표

<Callout type="goal">
  - 파이게임이 충돌을 **어떻게 판단하는지** 설명할 수 있다.
  - 스프라이트를 **여러 그룹에 동시에** 넣는 이유를 말할 수 있다.
  - `spritecollide` 와 `groupcollide` 의 차이를 설명할 수 있다.
  - `dokill` 인자가 무엇을 하는지 말할 수 있다.
</Callout>

## 1단계 · 충돌은 사각형 겹침이다냥 (6분)

<Callout type="important">
  파이게임의 스프라이트는 **진짜 물체가 아니다냥.** 그냥 그림이다냥.
  그래서 "부딪혔다" 는 건 물리가 아니라 **계산**이다냥.

  각 스프라이트의 `rect`(3강에서 배운 그 사각형)가 **겹치는지**를 본다냥.
</Callout>

```
  ┌────────┐
  │ 운석   │
  │   ┌────┼────┐
  └───┼────┘    │      ← 사각형이 겹쳤다냥 = 충돌!
      │ 미사일 │
      └────────┘
```

<Callout type="tip">
  그래서 그림이 동그래도 판정은 **네모**로 된다냥.
  운석 모서리 근처에서 "안 맞은 것 같은데 맞았다" 는 일이 생기는 이유다냥.
  더 정확한 판정 방법도 있지만, 대부분의 게임은 이 정도로 충분하다냥.
</Callout>

## 2단계 · 왜 그룹을 나누냥? (10분)

지금은 **모든 것이 `all_sprite_group` 하나**에 들어 있다냥.
배경도, 우주선도, 미사일도, 운석도 전부다냥.

그런데 충돌을 확인하려면 이렇게 물어봐야 한다냥.

> "우주선이 **운석들**과 부딪혔냥?"

`all_sprite_group` 에 물어보면 **배경이랑도 부딪혔다** 고 나온다냥.
그래서 **운석만 모아둔 그룹**이 따로 필요하다냥.

<Callout type="important">
  한 스프라이트는 **여러 그룹에 동시에 들어갈 수 있다냥.**

  운석은
  - `all_sprite_group` 에 → 그려지기 위해
  - `meteor_sprite_group` 에 → 충돌 판정을 위해

  둘 다 들어간다냥. 명함을 **두 개의 명함첩에 꽂아두는 것**이다냥.
</Callout>

```python
super().__init__((all_sprite_group, meteor_sprite_group))   # 튜플로 넘긴다냥
```

`Sprite` 의 초기화는 그룹을 **여러 개 받을 수 있다냥.**
괄호로 묶어서 넘기면 전부 등록된다냥.

<StepCard step="spritecollide" title="주인공 하나가 무리와 부딪혔나">

```python
collision = pygame.sprite.spritecollide(player, meteor_sprite_group, False)
if collision:
    running = False        # 게임 오버!
```

**리스트를 돌려준다냥.** 파이썬에서 빈 리스트는 `False` 취급이라
`if collision:` 이라고만 써도 "부딪힌 게 있으면" 이 된다냥.

</StepCard>

<StepCard step="groupcollide" title="무리와 무리가 부딪혔나">

```python
pygame.sprite.groupcollide(meteor_sprite_group, missile_sprite_group, True, True)
```

미사일 하나하나, 운석 하나하나를 **직접 짝지어 비교할 필요가 없다냥.**
이 한 줄이 전부 처리한다냥.

</StepCard>

## 4단계 · dokill — 부딪히면 없앨까? (8분)

두 함수 모두 마지막에 **`dokill`** 이라는 참/거짓 인자를 받는다냥.

```python
spritecollide(player, meteor_group, False)
#                                   └── 부딪힌 운석을 없앨까? 아니오
```

  right={{
    label: 'dokill = True',
    color: 'red',

      '부딪히면 kill()해서 없앤다',
      '미사일 vs 운석에 쓴다',
      '미사일도 사라지고 운석도 터진다',
      '9강에서 배운 kill()을 대신 불러준다',
    ],
  }}
/>

`groupcollide` 는 **양쪽 다** 정할 수 있어서 인자가 두 개다냥.

```python
groupcollide(meteor_group, missile_group, True, True)
#                                          └앞  └뒤
#                            운석을 없앨까?  미사일을 없앨까?
```

<Callout type="tip">
  `True, False` 로 하면 어떻게 되냥?
  **운석만 터지고 미사일은 살아남는다냥.** 관통 미사일이 되는 것이다냥!
  실습에서 직접 바꿔보자냥.
</Callout>

## 5단계 · 그룹 전달 지옥과 리팩토링 (10분)

여기서 문제가 하나 생긴다냥.

미사일도 `missile_sprite_group` 에 넣어야 하는데,
**미사일을 만드는 건 우주선**이다냥(9강).

```
main.py가 그룹을 만들고
  → Player에게 그룹을 넘기고
    → Player가 그걸 들고 있다가
      → Missile에게 다시 넘긴다
```

그룹이 세 개가 되면 **인자가 줄줄이 늘어난다냥.** 코드가 지저분해진다냥.

<Callout type="analogy">
  택배를 받을 때마다 **옆집을 거쳐서** 받는 것과 같다냥.
  옆집은 아무 상관도 없는데 계속 짐을 들고 있어야 한다냥.
</Callout>

### 해결: 그룹을 settings.py로 옮긴다냥

```python
# settings.py
all_sprite_group = pygame.sprite.Group()
meteor_sprite_group = pygame.sprite.Group()
missile_sprite_group = pygame.sprite.Group()
```

그러면 **필요한 클래스가 직접 가져다 쓴다냥.**

```python
# entity/missile.py
from settings import all_sprite_group, missile_sprite_group

class Missile(pygame.sprite.Sprite):
    def __init__(self, pos):                              # group 인자가 사라졌다냥!
        super().__init__((all_sprite_group, missile_sprite_group))
```

<Callout type="important">
  10강에서 `display_surface` 를 `settings.py` 로 옮긴 것과 **같은 이유**다냥.
  여러 곳에서 함께 쓰는 것은 한곳에 두고 **필요한 쪽이 직접 가져가는 게** 깔끔하다냥.

  덕분에 `main.py` 도 짧아진다냥.

  ```python
  Background()          # 인자가 없다냥
  player = Player()
  Meteor.spawn(3)
  ```
</Callout>
