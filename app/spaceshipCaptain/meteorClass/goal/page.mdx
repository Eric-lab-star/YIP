## 1단계 · 랜덤으로 다양하게 (8분)

운석 100개가 전부 같은 자리에서 같은 속도로 떨어지면 게임이 아니다냥.
**세 가지를 랜덤으로** 준다냥.

```python
self.rect = self.image.get_frect(
    center=(random.randint(0, WINDOW_WIDTH),   # 가로 아무 데나
            random.randint(-100, 0))            # 화면 위쪽 바깥에서
)
self.speed = random.randint(300, 500)                        # 속도
self.direction = pygame.Vector2(random.randint(-1, 1), 1)    # 방향
```

<StepCard step="위치" title="화면 위쪽 바깥에서 시작">

y를 `-100 ~ 0` 으로 준다냥. **화면 밖 위쪽**이다냥.
그래야 운석이 화면 안에서 갑자기 튀어나오지 않고
**위에서 스르륵 들어오는** 것처럼 보인다냥.

</StepCard>

<StepCard step="속도" title="300~500 사이 아무 값">

빠른 운석과 느린 운석이 섞여야 피하는 재미가 생긴다냥.

</StepCard>

<StepCard step="방향" title="x는 -1, 0, 1 중 하나 / y는 항상 1">

`random.randint(-1, 1)` 은 `-1`, `0`, `1` 중 하나를 준다냥.
왼쪽 아래·똑바로 아래·오른쪽 아래로 비스듬히 떨어진다냥.
y가 `1` 로 고정이라 **항상 아래로는 간다냥.**

</StepCard>

<Callout type="tip">
  미사일과 반대로 **화면 아래로 나가면** 사라져야 한다냥.

  ```python
  if self.rect.top > WINDOW_HEIGHT:
      self.kill()
  ```

  운석의 **위쪽 변**이 화면 바닥보다 아래로 갔다는 건 완전히 나갔다는 뜻이다냥.
</Callout>

## 2단계 · @classmethod — 공장 만들기 (8분)

운석을 10개 만들려면 `Meteor(group)` 을 열 번 써야 하냥? 귀찮다냥.

```python
    @classmethod
    def spawn(cls, group, n):
        for _ in range(n):
            Meteor(group)
```

이러면 한 줄로 끝난다냥.

```python
Meteor.spawn(all_sprite_group, 10)
```

<Callout type="analogy">
  `@classmethod` 는 **붕어빵 가게 주인에게 주문하는 것**이다냥.

  - 보통 메서드는 **붕어빵 하나**에게 말을 거는 것이다냥 (`붕어빵.먹기()`)
  - 클래스 메서드는 **가게 자체**에게 말을 거는 것이다냥 (`붕어빵가게.다섯개주세요()`)

  붕어빵을 먼저 하나 사지 않아도 주문할 수 있다냥!
</Callout>

## 3단계 · 커스텀 이벤트 — 알람 맞추기 (10분)

운석이 처음에 10개 나오고 끝나면 안 된다냥. **계속 나와야 한다냥.**

"0.4초마다 운석 3개" 를 어떻게 만드냥?

<Callout type="analogy">
  **학교 시간표에 없던 "간식 시간" 을 내가 직접 만들어 등록하는 것**과 같다냥.

  1. 새 이벤트 종류를 만든다냥 (간식 시간이라는 걸 정한다)
  2. 알람을 맞춘다냥 (0.4초마다 울려라)
  3. 게임 루프에서 그 알람을 듣는다냥 (울리면 운석을 만든다)
</Callout>

```python
meteor_event = pygame.event.custom_type()      # ① 새 이벤트 만들기
pygame.time.set_timer(meteor_event, 400)       # ② 0.4초마다 울려라

while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False
        if event.type == meteor_event:          # ③ 울렸으면
            Meteor.spawn(all_sprite_group, 3)   #    운석 3개!
```

<Callout type="important">
  1강에서 배운 `pygame.event.get()` 이 여기서 다시 나온다냥.
  그때는 **창 닫기(QUIT)** 만 봤는데,
  이제 **내가 만든 이벤트**도 같은 곳으로 들어온다냥.
  이벤트 접수함 하나로 전부 처리하는 것이다냥.
</Callout>

## 4단계 · 최적화 — 밀가루를 한 포대 사두기 (12분)

지금 코드에는 문제가 하나 있다냥.

```python
def __init__(self, group):
    self.image = pygame.image.load(Meteor.path).convert_alpha()
```

**운석이 하나 생길 때마다** 하드디스크에서 `meteor.png` 를 다시 읽는다냥.

<Callout type="analogy">
  붕어빵을 하나 구울 때마다 **밀가루를 사러 마트에 다녀오는 것**과 같다냥.
  운석 100개면 마트에 100번 다녀온다냥!
</Callout>

디스크에서 파일을 읽는 건 메모리에서 꺼내는 것보다 **훨씬 느리다냥.**
게다가 똑같은 이미지가 메모리에 100개나 올라간다냥.

### 해결: 클래스 변수로 딱 한 번만

```python
class Meteor(pygame.sprite.Sprite):
    path: str = join("images", "meteor.png")
    surf: pygame.Surface = pygame.image.load(path).convert_alpha()   # 여기!

    def __init__(self, group):
        super().__init__(group)
        self.image = Meteor.surf        # 모두가 같은 이미지를 공유한다냥
```

6강에서 배운 **게시판(클래스 변수)** 이다냥.
모든 운석이 같은 그림 하나를 함께 본다냥.

## 5단계 · 여기서 함정이 하나 있다냥 (7분)

<Callout type="important">
  클래스 변수에 적힌 코드는 **언제 실행되냥?**

  `__init__` 이 불릴 때가 아니다냥.
  파이썬이 `class Meteor:` 라는 **정의문을 읽는 순간**, 즉 그 파일이
  `import` 되는 바로 그때 **딱 한 번** 실행된다냥.
</Callout>

<Callout type="analogy">
  빵집이 **문을 여는 아침에 주인이 반죽을 미리 만들어두는 것**과 같다냥.
  손님이 한 명도 안 왔지만 빵집이라는 가게가 세워지는 순간에 이미 준비가 끝난다냥.
</Callout>

그런데 `convert_alpha()` 는 **화면이 이미 만들어져 있어야** 쓸 수 있다냥(3강에서 배웠다냥).
그래서 순서 문제가 생긴다냥.

```
main.py가 entity/meteor.py를 import
    → class Meteor 정의문을 읽음
    → pygame.image.load(...).convert_alpha() 실행
    → 그런데 아직 화면이 없다냥! 오류!
```

### 해결: 화면 만들기를 settings.py로 옮긴다냥

```python
# settings.py
import pygame

WINDOW_WIDTH, WINDOW_HEIGHT = 1280, 720

pygame.init()
display_surface = pygame.display.set_mode((WINDOW_WIDTH, WINDOW_HEIGHT))
pygame.display.set_caption("space shooter")
```

`meteor.py` 는 `settings` 를 먼저 `import` 하니
**화면이 먼저 만들어지고** 그다음에 이미지가 로드된다냥.

<Callout type="tip">
  게임 설정과 관련된 것들을 `settings.py` 한곳에 모으는 것은
  8강에서 배운 **모듈로 나누기**의 연장이기도 하다냥.
  이제 `main.py` 는 게임 루프에만 집중한다냥.
</Callout>
