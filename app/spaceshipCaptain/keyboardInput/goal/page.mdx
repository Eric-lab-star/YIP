## 1단계 · 키보드 상태 읽기 (6분)

<Callout type="analogy">
  `pygame.key.get_pressed()` 는 **키보드 전체를 한 장에 찍은 사진**이다냥.
  지금 이 순간 어떤 키가 눌려 있는지를 전부 담아서 돌려준다냥.
</Callout>

```python
keys = pygame.key.get_pressed()

keys[pygame.K_w]    # W가 눌려 있으면 True, 아니면 False
keys[pygame.K_a]    # A가 눌려 있으면 True
```

여기서 중요한 건 **"눌려 있는 동안 계속 True"** 라는 점이다냥.
키를 꾹 누르고 있으면 매 프레임 True가 나온다냥.
그래서 캐릭터를 **부드럽게 계속 움직일 때** 딱 맞다냥.

<Callout type="note">
  이벤트로 키를 받는 방법(`pygame.KEYDOWN`)도 있다냥.
  그건 **누른 순간 딱 한 번**만 반응한다냥.
  점프나 발사처럼 "한 번만" 일어나야 하는 동작에 쓴다냥.
  실제로 다음다음 챕터에서 미사일 발사에 그걸 쓴다냥.
</Callout>

## 2단계 · 방향은 매 프레임 새로 정한다냥 (8분)

```python
direction = pygame.Vector2(0, 0)     # 매 프레임 "정지"에서 시작
if keys[pygame.K_w]:
    direction.y = -1
```

왜 매번 `(0, 0)` 으로 되돌리냥?
**키에서 손을 떼면 멈춰야 하기 때문**이다냥.

<Callout type="important">
  방향을 초기화하지 않으면 지난 프레임의 방향이 그대로 남는다냥.
  W를 눌렀다 떼도 우주선이 계속 위로 날아간다냥.

  매 프레임 **"나는 지금 어디로 가야 하지?"** 를 새로 묻는 구조여야 한다냥.
</Callout>

### 파이게임의 y는 아래가 커진다냥

W(위)를 눌렀을 때 `direction.y = -1` 인 게 이상해 보인다냥?
지난 시간에 배운 대로 **화면 맨 위가 y=0** 이고 아래로 갈수록 커진다냥.
그래서 위로 가려면 **빼야** 한다냥.

## 3단계 · if를 뺄셈 한 줄로 (7분)

`if` 를 네 번 쓰는 대신 이렇게 쓸 수 있다냥.

```python
direction.x = int(keys[pygame.K_d]) - int(keys[pygame.K_a])
direction.y = int(keys[pygame.K_s]) - int(keys[pygame.K_w])
```

<Callout type="analogy">
  **줄다리기**라고 생각하면 된다냥.
  오른쪽 힘에서 왼쪽 힘을 뺀 게 최종 방향이다냥.

  - D만 누름 → `1 - 0 = 1` (오른쪽)
  - A만 누름 → `0 - 1 = -1` (왼쪽)
  - 둘 다 누름 → `1 - 1 = 0` (제자리)
  - 둘 다 안 누름 → `0 - 0 = 0` (제자리)
</Callout>

`int(True)` 는 `1`, `int(False)` 는 `0` 이라는 성질을 이용한 것이다냥.
네 줄짜리 `if` 가 한 줄이 되고, **양쪽을 동시에 누르는 경우까지** 저절로 처리된다냥.

## 4단계 · 대각선이 더 빠른 이유 (10분)

여기가 오늘의 핵심이다냥.

W와 D를 같이 누르면 `direction` 은 `(1, -1)` 이 된다냥.
이 화살표의 **길이**가 얼마냥?

```
가로 1, 세로 1인 직각삼각형의 빗변
= 약 1.414
```

/>

<Callout type="analogy">
  **같은 보폭으로 걸어도 대각선으로 가면 더 멀리 간다냥.**
  정사각형 교실을 가로질러 가는 것과 벽을 따라 가는 것의 차이다냥.
</Callout>

### 해결: 정규화(normalize)

정규화는 **방향은 그대로 두고 길이만 1로 맞추는** 것이다냥.

```python
if direction.length() > 0:
    direction.normalize_ip()
```

`(1, -1)` 은 `(0.707, -0.707)` 이 된다냥.
방향은 여전히 오른쪽 위인데, 길이는 1이라 **다른 방향과 속도가 같아진다냥.**

<Callout type="important">
  `if direction.length() > 0:` 이 꼭 필요하다냥.
  아무 키도 안 눌렀으면 `direction` 은 `(0, 0)` 이고,
  **길이 0짜리 화살표는 길이를 1로 만들 수 없다냥.**
  그냥 정규화하면 오류가 난다냥.
</Callout>

<Callout type="tip">
  이름 끝의 `_ip` 는 **in place**, 즉 "그 자리에서 바꾼다" 는 뜻이다냥.
  새 벡터를 돌려주는 게 아니라 `direction` 자체를 고친다냥.
  `clamp_ip` 도 같은 규칙이다냥.
</Callout>

## 5단계 · 화면 밖으로 못 나가게 (4분)

```python
player_rect.clamp_ip(pygame.Rect(0, 0, WINDOW_WIDTH, WINDOW_HEIGHT))
```

`clamp` 는 **가둔다** 는 뜻이다냥.
우주선 사각형이 화면 사각형 밖으로 나가면 경계에 딱 붙여준다냥.
지난 시간처럼 튕기는 게 아니라 **더 못 나가게 막는** 것이다냥.
