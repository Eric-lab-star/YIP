## 4단계 · 그런데 문서는 어떻게 넣냥? — 인덱싱 (5분)

<NyangSpeech mood="WARN">
  잠깐! 위의 네 정거장은 전부 **질문이 들어온 다음**의 이야기다냥. 그 전에
  꼭 필요한 준비가 하나 있다냥 — 바로 **내 문서를 벡터DB에 넣어두는 일**이라냥.
  지금까지는 코드에 예시 문장을 직접 적었지만, 진짜 RAG는 **실제 문서 파일**을
  통째로 읽어서 넣는다냥!
</NyangSpeech>

도서관에 비유하면, 손님을 맞이하기 전에 **신간 도서를 입고**하는 작업이라냥. 책이 도착하면(파일 읽기) → 분류하고(청킹) → 서가에 꽂아두는(벡터DB 저장) 것이지냥. 이 준비 과정을 **인덱싱(indexing)**이라고 부른다냥.

<StepCard step="준비" title="문서 인덱싱 세 걸음">

1. **파일 읽기** — `open()`으로 문서 파일(`.txt`)을 통째로 읽어온다냥.
2. **청킹** — **빈 줄(문단) 기준**으로 나눈다냥. 문장이 중간에 끊기지 않아 검색이 잘 된다냥.
3. **저장** — 청크들을 벡터DB에 `add()` 한다냥.

</StepCard>

코드로 보면 이 세 걸음이 그대로 이어진다냥.

```python
# 1) 문서 파일을 통째로 읽기
with open("school_guide.txt", "r", encoding="utf-8") as f:
    document = f.read()

# 2) 빈 줄(문단) 기준으로 청킹하기
paragraphs = document.split("\n\n")
chunks = [p.strip() for p in paragraphs if p.strip()]

# 3) 벡터DB에 저장하기 (upsert = 다시 실행해도 안전하게 덮어쓰기)
ids = [f"chunk_{i}" for i in range(len(chunks))]
collection.upsert(documents=chunks, ids=ids)
```

<Callout type="note">
  **여기서 `collection`은 제미나이 임베딩으로 만든, 디스크에 저장되는 서랍장이라냥!**

  Chroma의 기본 임베딩 모델은 **영어 위주로 학습**되어 있어서, 한국어 문서를
  검색하면 엉뚱한 청크를 꺼내오기도 한다냥. 그래서 우리는 1차시부터 써온
  **제미나이 임베딩**을 Chroma에 연결해서 쓴다냥. 그리고 3차시에서 배운 대로
  `chromadb.PersistentClient`로 만들어서, 코드를 다시 실행해도 인덱싱한 내용이
  그대로 남아있게 한다냥. 연결하는 코드는 실습 페이지에서 직접 만나볼 거다냥!
</Callout>

### PDF는 어떻게 넣냥?

<NyangSpeech mood="ASK">
  여기서 손이 번쩍 올라올 것 같다냥. "선생님, 제 자료는 `.txt`가 아니라 **PDF**인데요?"
  좋은 질문이다냥! 교재, 가정통신문, 안내 책자 같은 진짜 자료는 대부분 PDF라냥.
  그런데 걱정할 필요 없다냥 — **글자만 뽑아내면 그 다음은 위와 완전히 똑같다냥!**
</NyangSpeech>

`pypdf`라는 도구를 쓰면 PDF에서 글자를 꺼낼 수 있다냥. `.txt`는 `open()`으로 바로 읽었지만, PDF는 **페이지를 하나씩 돌면서** 글자를 뽑아 이어붙이는 한 걸음이 더 붙는 것뿐이라냥.

```python
# 먼저 설치가 필요하다냥: pip install pypdf
from pypdf import PdfReader

# 1) PDF 열기
reader = PdfReader("school_guide.pdf")

# 2) 페이지마다 글자를 뽑아 이어붙이기 (페이지 사이는 빈 줄로 구분)
#    layout 모드로 뽑아야 문단 사이의 빈 줄이 살아있다냥!
document = ""
for page in reader.pages:
    document += page.extract_text(extraction_mode="layout") + "\n\n"

# 3) 여기부터는 .txt와 똑같다냥 — 빈 줄 기준 청킹 후 저장
paragraphs = document.split("\n\n")
chunks = [p.strip() for p in paragraphs if p.strip()]
```

<Callout type="tip">
  **핵심은 이거다냥!** PDF든 `.txt`든, 벡터DB에 들어가는 건 결국 **똑같은 텍스트 청크**라냥.
  그래서 바뀌는 건 **맨 앞의 "읽는 방법"** 하나뿐이고, 청킹과 저장은 손댈 필요가 없다냥.
</Callout>

<Callout type="important">
  **`extraction_mode="layout"`을 빼먹으면 안 된다냥!**

  `extract_text()`를 그냥 부르면, PDF에서 눈에 보이던 **문단 사이 빈 줄이 사라진다냥.**
  줄바꿈(`\n`)만 남고 빈 줄(`\n\n`)은 하나도 안 만들어져서, `split("\n\n")`으로 잘라도
  **페이지 한 장이 통째로 청크 하나**가 되어버린다냥. 기껏 문단 기준으로 자르기로 해놓고
  거대한 덩어리 하나를 넣는 셈이라냥.

  `extraction_mode="layout"`은 글자의 **화면상 위치**를 보고 뽑기 때문에, 문단 사이가
  벌어져 있으면 그만큼 빈 줄을 남겨준다냥. 그래서 우리가 쓰는 빈 줄 기준 청킹이 통한다냥.

  실제로 4개 절이 담긴 한 쪽짜리 안내문으로 확인해보면 이렇게 갈린다냥.

  | 방식 | 결과 |
  |---|---|
  | `extract_text()` | 청크 **1개** (412자, 페이지 통째로) |
  | `extract_text(extraction_mode="layout")` | 청크 **5개** (18 · 79 · 107 · 101 · 103자) |

  빈 줄이 여러 개 연달아 나오기도 하지만, 우리 코드에는 `if p.strip()`이 있어서
  빈 조각은 알아서 걸러진다냥.
</Callout>

<Callout type="note">
  **주의 두 가지다냥.**

  1. `extract_text()`는 **글자로 된 PDF**에서만 글자를 뽑을 수 있다냥. 사진을 찍거나
     스캔해서 만든 PDF는 글자가 아니라 **그림**이라서 아무것도 안 나온다냥
     (빈 문자열이 나온다냥). 그럴 땐 글자가 살아있는 PDF를 쓰거나, 나중에
     **OCR**(그림 속 글자를 읽어내는 기술)을 배우면 된다냥.
  2. `.txt`로 넣은 청크와 **같은 `ids`**를 쓰면 `upsert`가 기존 내용을 덮어써버린다냥.
     PDF는 `pdf_chunk_0`처럼 **이름을 다르게** 붙여주자냥.
</Callout>

<Callout type="important">
  **인덱싱은 한 번, 질문은 여러 번!**

  책을 서가에 꽂는 건 한 번이면 되지만, 손님은 계속 찾아온다냥.
  마찬가지로 인덱싱은 문서가 바뀌지 않는 한 **한 번만** 해두면 되고,
  그 뒤로는 질문이 들어올 때마다 **검색 → 생성**만 반복된다냥.
  학교 안내문이든, 동아리 소개글이든, 내가 정리한 노트든 —
  **어떤 문서라도** 이렇게 넣어주면 AI가 그 문서의 전문가가 된다냥!

  단, **Streamlit처럼 화면과 연결된 앱**은 버튼을 누를 때마다 코드 전체가
  처음부터 다시 실행된다냥. 그래서 인덱싱 코드를 그대로 두면 질문할 때마다
  또 인덱싱을 반복하게 된다냥 — 이 문제를 실습 페이지에서
  `@st.cache_resource`로 깔끔하게 해결해볼 거다냥!
</Callout>

## 5단계 · 코드로 미리 보는 RAG 함수 (3분)

<NyangSpeech mood="TEACH">
  실습에서 직접 빈칸을 채워볼 거지만, 먼저 RAG 함수가 어떻게 생겼는지
  구경만 해보자냥. 위에서 배운 4단계가 코드에 그대로 들어 있다냥!
</NyangSpeech>

```python
from google import genai

genai_client = genai.Client(api_key="여기에 본인의 제미나이 API 키 입력")

# 인덱싱 때 제미나이 임베딩으로 만들어둔 collection을 그대로 사용

def rag_answer(question):
    # 1) 벡터DB에서 관련 청크 검색 (Retrieval)
    results = collection.query(query_texts=[question], n_results=2)
    retrieved_chunks = results["documents"][0]

    # 2) 검색된 내용을 하나의 문자열로 합치기
    context = "\n".join(retrieved_chunks)

    # 3) 검색 결과 + 질문을 prompt로 구성
    prompt = f"""
    아래 [참고 자료]만을 근거로 질문에 답해줘.

    [참고 자료]
    {context}

    [질문]
    {question}
    """

    # 4) 제미나이가 답변 생성 (Generation)
    response = genai_client.models.generate_content(model="gemini-3.5-flash", contents=prompt)
    return response.text
```

보이냥? `collection.query(...)`가 **검색**, `genai_client.models.generate_content(...)`가 **생성**이라냥. 그 사이에서 검색 결과를 prompt에 끼워넣는 게 RAG의 핵심이라냥!

<Callout type="note">
  걱정 말라냥! 실습 페이지에서는 **실제 문서 파일을 직접 인덱싱**하고, prompt 안의 **역할**과 **테스트 질문**도 직접 채워볼 거다냥. 지금은 "아, 이렇게 생겼구나" 정도만 느끼면 충분하다냥.
</Callout>
