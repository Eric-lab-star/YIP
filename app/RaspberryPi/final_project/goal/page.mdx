# 최종프로젝트

21번의 수업 동안 여러분의 도구 상자에는 많은 것이 쌓였어요.
LED와 버튼, 다섯 가지 센서, 카메라와 마이크, 파일 저장, 블루투스와 웹서버,
그리고 사물인식까지.
마지막 수업은 새로운 부품을 배우는 시간이 아니에요.
**이 조각들을 엮어 세상에 하나뿐인 내 작품을 만드는 시간**입니다.

<Callout type="goal">

**이번 수업을 마치면**

1. 해결하고 싶은 문제에서 출발해 프로젝트를 설계할 수 있어요.
2. 큰 목표를 작은 단계로 쪼개어 하나씩 완성할 수 있어요.
3. 완성한 작품을 다른 사람에게 설명할 수 있어요.

</Callout>

## 1. 모든 작품의 뼈대는 이미 알고 있어요

과정 내내 반복된 문장을 기억하나요?

**입력 → 판단 → 출력**

우리가 배운 모든 것은 이 세 자리 중 하나에 들어갑니다.

| 입력 (세상을 읽기) | 판단 (프로그램) | 출력 (세상에 작용하기) |
| --- | --- | --- |
| 버튼, CDS, MQ-2 | 조건문, 반복문 | LED, 부저 |
| 초음파, MPU6050, DS18B20 | 함수, 이벤트 | 화면, 파일 저장 |
| 카메라, 마이크, 웹 요청, BLE | 사물인식 모델 | 웹 응답, 사진·녹음 |

프로젝트 설계란 결국 **이 표에서 조각을 골라 연결하는 일**이에요.
"어두워지면(CDS) + 사람이 지나갈 때만(초음파) + 불을 켠다(LED)" —
조각 세 개를 이으니 벌써 스마트 가로등이 되었죠.

## 2. 설계의 순서: 만들기 전에 그리기

좋은 프로젝트는 납땜이 아니라 **질문**에서 시작해요. 이 순서를 따라가 봅시다.

### 1단계: 문제 정하기

"무엇이 불편하지?", "무엇이 궁금하지?"에서 출발해요.
"동생이 내 방에 몰래 들어와요", "우리 화분이 자꾸 말라요"처럼
**내 생활의 진짜 문제**일수록 좋은 주제예요.

### 2단계: 입력·판단·출력으로 쪼개기

문제를 세 자리에 맞춰 적어 봐요.
화분 지킴이라면 이렇게요.

- 입력: 흙이 마른 것을 어떻게 알까? → 온도센서? 일단 **온도와 시간 기록**으로 시작해 보자.
- 판단: 언제 알려야 할까? → 기록을 보고 기준을 정하자.
- 출력: 어떻게 알릴까? → LED? 웹페이지에 표시?

### 3단계: 가장 작은 버전 먼저

처음부터 완성품을 만들려 하면 어디서 막혔는지 알 수 없게 돼요.
**오늘 당장 동작하는 가장 작은 버전**을 먼저 정합니다.
화분 지킴이의 가장 작은 버전은 "10분마다 온도를 파일에 기록하기" 정도겠죠.
그것이 돌아간 **다음에** LED를 더하고, 그다음에 웹페이지를 더해요.

<Callout type="important">

**한 번에 한 조각씩, 그리고 바로 확인해요.**

부품 다섯 개를 다 연결하고 긴 코드를 한 번에 돌리면, 안 될 때 범인을 찾을 수 없어요.
과정 내내 우리가 연습한 방법을 믿으세요.

- 센서 하나를 달면 **그 값부터 화면에 찍어** 확인하고 다음으로 넘어가요.
- 안 되면 지난 수업들의 점검 목록으로 돌아가요. 배선 → 핀 번호 → 코드 순서였죠.
- 배선을 바꿀 때는 **전원 분리**, GPIO에 5V 금지. 마지막 날까지 지키는 약속이에요.

</Callout>

## 3. 아이디어 창고

막막할 때 출발점으로 삼을 만한 조합들이에요. 그대로 만들어도 좋고 바꿔도 좋아요.

- **스마트 가로등**: CDS + 초음파 + LED. 어두울 때 사람이 지나가면 켜져요.
- **우리 반 온도 기록장**: DS18B20 + 파일 저장 + 웹서버. 교실 온도를 기록하고 웹으로 보여 줘요.
- **문 지킴이**: 초음파(또는 카메라 + 사물인식) + 부저 + 사진 저장. 누가 다가오면 알리고 찍어요.
- **움직임 알림 상자**: MPU6050 + LED + 녹음. 상자가 움직이면 경고음을 재생해요.
- **원격 조명 리모컨**: 웹서버 + LED 여러 개. 폰으로 방마다 불을 켜고 꺼요.
- **가스 안전 모니터**: MQ-2 + LED + 웹페이지 상태 표시. 수업에서 배운 안전 수칙을 지키며 시험해요.

## 4. 발표: 작품의 절반

완성만큼 중요한 것이 **설명**이에요. 발표에는 이 네 가지를 담아요.

1. **왜** 이걸 만들었나요? (문제)
2. **어떻게** 동작하나요? (입력 → 판단 → 출력의 흐름)
3. **어디서 막혔고** 어떻게 해결했나요? (가장 값진 부분이에요)
4. 시간이 더 있다면 **무엇을 더하고** 싶나요?

막혔던 이야기는 부끄러운 것이 아니라 발표의 하이라이트예요.
문제를 찾아 해결한 과정이야말로 여러분이 이 과정에서 배운 진짜 능력이니까요.

만들기 전에 문제를 입력, 판단, 출력의 세 자리로 쪼개어 설계해요.
어떤 센서로 읽고, 무엇을 기준으로 판단하고, 무엇으로 표현할지 그려 본 다음에 부품을 잡습니다.

</details>

<details>
<summary>2. "가장 작은 버전부터 만들기"가 중요한 이유는 무엇인가요?</summary>

한 번에 다 만들면 안 될 때 어느 부분이 문제인지 찾을 수 없기 때문이에요.
작게 만들어 동작을 확인하고 한 조각씩 더하면, 문제가 생겨도 방금 더한 부분만 보면 됩니다.

</details>

<details>
<summary>3. 발표에서 "막혔던 이야기"를 하는 이유는 무엇인가요?</summary>

문제를 발견하고 원인을 찾아 해결하는 과정이 이 과정에서 배운 가장 중요한 능력이기 때문이에요.
같은 문제를 만날 친구들에게도 가장 도움이 되는 내용입니다.

</details>
