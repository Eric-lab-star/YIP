# 초음파센서 실습

오늘은 라즈베리파이에게 박쥐의 능력을 달아 줍니다.
전압 분배 회로를 직접 꾸미고, 센서가 알려 주는 거리가 자로 잰 거리와 맞는지 시험해 봐요.

<Callout type="goal">

**이번 실습을 마치면**

1. 저항 두 개로 Echo 신호를 낮춘 HC-SR04 회로를 만들 수 있어요.
2. 센서가 잰 거리를 자로 잰 거리와 비교해 표로 적을 수 있어요.
3. 다섯 번 잰 평균으로 물체가 가까운지 먼지 판단하는 프로그램을 만들 수 있어요.

</Callout>

<Callout type="important">

**배선 전 약속**

- 배선을 바꿀 때는 **먼저 전원을 완전히 분리**해요.
- GPIO 신호 핀은 **3.3V**까지만 다뤄요. 오늘은 5V 핀을 쓰지만, 5V 선은 **센서의 VCC로만** 가요.
- **Echo를 GPIO24에 바로 연결하면 안 돼요.** Echo의 약 5V 신호는 반드시 두 저항을 거쳐 약 3.3V로 낮춘 뒤에 들어가야 해요.
- 전원을 넣기 전에 친구나 선생님과 배선을 한 번 더 확인해요.

</Callout>

## 준비물

- [ ] 라즈베리파이와 전원 어댑터 (모니터, 키보드, 마우스 연결)
- [ ] 브레드보드
- [ ] HC-SR04 초음파 센서 1개
- [ ] 1k옴 저항 1개, 2k옴 저항 1개 (봉지 표시로 값을 확인해요)
- [ ] 암-수 점퍼선 4개
- [ ] 자 또는 줄자, 시험용 책 1권

코드의 따옴표 안에 있는 한글이 입력되지 않으면 영어로 바꿔도 돼요.

<MissionCard number={1} title="전압 분배 회로 만들기" time="15분">

**Echo 신호의 길:** Echo → 1k옴 저항 → 가운데 지점(여기서 GPIO24로) → 2k옴 저항 → GND

가운데 지점의 전압은 5V × 2k ÷ (1k + 2k) = **약 3.3V**예요.

1. 라즈베리파이의 전원을 끄고 어댑터를 뽑아요.
2. 센서를 브레드보드에 꽂아요. 두 원통이 브레드보드 바깥쪽을 보게 하고, 핀 옆에 적힌 글자를 읽어 VCC, Trig, Echo, GND 순서인지 확인해요. 순서가 다르면 글자를 따라 표의 줄을 바꿔요.
3. 아래 표대로 하나씩 꽂아요.

| 부품 | 한쪽 | 다른 쪽 |
| --- | --- | --- |
| HC-SR04 | VCC a1, Trig a2 | Echo a3, GND a4 |
| 점퍼선 1 | 물리 핀 2 (5V) | 브레드보드 b1 |
| 점퍼선 2 | 물리 핀 16 (GPIO23) | 브레드보드 b2 |
| 1k옴 저항 | c3 | c8 |
| 2k옴 저항 | e4 | e8 |
| 점퍼선 3 | 물리 핀 18 (GPIO24) | 브레드보드 b8 |
| 점퍼선 4 | 물리 핀 6 (GND) | 브레드보드 b4 |

4. 줄마다 맞는지 확인해요. 3번 줄에는 Echo와 1k옴 저항만, 8번 줄에는 두 저항과 GPIO24 선만 있어야 해요. **GPIO24 선이 3번 줄에 있으면 안 돼요.**
5. 확인이 끝나면 전원을 연결하고 바탕화면이 나올 때까지 기다려요.

**성공 확인:** 친구가 손가락으로 Echo 신호의 길을 따라가며 저항 두 개를 모두 지나는지 확인해 줘요. 전원을 넣어도 연기나 타는 냄새가 나지 않아요. 이상하면 바로 전원을 뽑고 선생님을 불러요.

</MissionCard>

<MissionCard number={2} title="자로 재서 센서와 비교하기" time="15분">

Thonny 편집기에 아래 코드를 입력하고 `distance.py`로 저장한 뒤 **Run**을 눌러요.

```python
from gpiozero import DistanceSensor
from time import sleep

sensor = DistanceSensor(echo=24, trigger=23, max_distance=4)

while True:
    distance_cm = sensor.distance * 100
    print(f"거리: {distance_cm:.1f} cm")
    sleep(0.5)
```

`max_distance=4`는 4m까지 재겠다는 뜻이에요.

1. 센서 앞에 책을 세우고 자로 거리를 재요.
2. 거리마다 숫자가 안정될 때까지 기다렸다가 공책에 표를 채워요.

| 자로 잰 거리 | 센서가 보여 준 거리 | 차이 |
| --- | --- | --- |
| 10cm | | |
| 30cm | | |
| 50cm | | |
| 100cm | | |

**성공 확인:** 책을 옮기면 숫자가 따라 변하고, 네 칸이 모두 채워졌어요.

이제 코드를 바꾸기 전에 **결과를 먼저 예상**해 봐요.

3. 벽에서 1.5m쯤 떨어진 곳에 센서를 놓고 벽을 재요. 숫자를 공책에 적어요.
4. 코드에서 `, max_distance=4`를 지우고 저장하면 같은 벽이 몇 cm로 나올까요? 예상을 적어요.
5. **Stop**을 누르고 다시 실행해서 예상과 비교해요. 비교가 끝나면 `max_distance=4`를 다시 넣어요.

**성공 확인:** 지운 뒤에는 숫자가 **100.0 cm**를 넘지 못해요. 기본값이 1m라서 그렇다는 것을 말할 수 있어요.

</MissionCard>

<MissionCard number={3} title="다섯 번 재서 판단하기" time="15분">

값 하나만 믿으면 한 번 튄 값에 판단이 흔들릴 수 있어요. `DistanceSensor`도 안에서 여러 번 재서 가운데 값을 골라 주지만, 우리도 여러 번 모아서 판단해 봐요.

1. 아래 코드를 `near_far.py`로 저장하고 실행해요.

```python
from gpiozero import DistanceSensor
from time import sleep

sensor = DistanceSensor(echo=24, trigger=23, max_distance=4)

while True:
    total = 0

    for i in range(5):
        total = total + sensor.distance * 100
        sleep(0.2)

    average = total / 5

    if average < 30:
        print(f"평균 {average:.1f} cm: 가까워요")
    else:
        print(f"평균 {average:.1f} cm: 멀어요")
```

2. 손바닥을 센서 앞 20cm에 두었다가 치워요. 화면이 몇 초 뒤에 바뀌는지 봐요.
3. 이번에는 손을 센서 앞으로 재빨리 한 번 휙 지나가게 해요. `가까워요`가 나오는지 관찰해요.

**성공 확인:** 약 1초마다 한 줄씩 나오고, 책이나 손을 20cm에 두면 `가까워요`, 치우면 `멀어요`가 나와요.

<Callout type="note">

`range(5)`를 `range(20)`으로 바꾸면 판단은 더 차분해지지만 그만큼 늦어져요.
자동차 후방 감지기라면 어느 쪽이 좋을지 친구와 이야기해 보세요.

</Callout>

</MissionCard>

## 막혔을 때

| 증상 | 확인할 곳 |
| --- | --- |
| 숫자가 나오지 않고 `DistanceSensorNoEcho` 경고가 떠요 | 전원을 분리하고 VCC가 핀 2, GND가 핀 6에 있는지, Trig와 Echo 줄이 바뀌지 않았는지 확인해요. |
| 값이 계속 0.0 cm이거나 터무니없어요 | 코드의 `echo=24, trigger=23`과 실제 배선이 같은지 확인해요. 두 번호가 바뀌는 실수가 흔해요. |
| 값이 안 변하고 제자리예요 | 1k옴과 2k옴 저항이 서로 바뀌지 않았는지 확인해요. 바뀌면 GPIO24에 닿는 전압이 너무 낮아져요. |
| 숫자가 100.0에서 멈춰요 | `max_distance=4`가 코드에 있는지 확인해요. |
| 숫자가 제멋대로 튀어요 | 수건처럼 소리를 흡수하는 물체 대신 평평한 책이나 벽으로 시험해요. 비스듬히 놓인 면도 잘 못 재요. |
| 프로그램이 시작하고 한동안 아무것도 안 나와요 | 첫 값은 여러 번 잰 뒤에 나와요. 몇 초 기다려도 그대로면 첫 번째 줄을 확인해요. |
| `GPIO busy`처럼 핀을 쓸 수 없다는 오류가 나요 | 이전 프로그램이 핀을 쓰고 있어요. Stop을 누르고 다시 실행해요. |
