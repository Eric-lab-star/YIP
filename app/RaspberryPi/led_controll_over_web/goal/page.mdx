# 웹으로 LED 제어하기

지난 시간에 만든 웹서버는 글자를 보여 줬어요.
오늘은 거기에 우리가 과정 내내 쌓아 온 기술을 **합체**합니다.
웹페이지의 버튼을 누르면 브레드보드의 LED가 켜지는,
**사물인터넷(IoT)**의 가장 작은 완성품을 만드는 날이에요.
집 밖에서 보일러를 켜는 앱의 원리가 오늘 책상 위에서 재현됩니다.

<Callout type="goal">

**이번 수업을 마치면**

1. 웹 요청이 GPIO 출력으로 이어지는 전체 경로를 설명할 수 있어요.
2. 주소(라우트)마다 다른 동작을 하는 서버를 만들 수 있어요.
3. 사물인터넷이 어떤 구조로 동작하는지 말할 수 있어요.

</Callout>

## 1. 두 세계를 잇는 다리

<SectionClip src={clipBase + "/ep01.mp4"} title="66화 — 두 세계를 잇는 다리" />

우리는 이미 두 가지를 할 줄 알아요.

- **Flask**: 주소로 요청이 오면 함수를 실행한다. (17차시)
- **gpiozero**: 함수에서 `led.on()`을 부르면 LED가 켜진다. (6차시)

그렇다면 다리는 간단해요. **요청이 왔을 때 실행되는 함수 안에서 LED를 켜면** 됩니다.

```python
from flask import Flask
from gpiozero import LED

app = Flask(__name__)
led = LED(17)

@app.route("/on")
def turn_on():
    led.on()
    return "LED를 켰어요"

@app.route("/off")
def turn_off():
    led.off()
    return "LED를 껐어요"

app.run(host="0.0.0.0", port=8080)
```

이게 전부예요. 실행한 뒤 스마트폰 브라우저에서
`http://라즈베리파이IP:8080/on`에 접속하면 **브레드보드의 LED가 켜집니다.**
`/off`로 끄고요. 주소창이 리모컨이 된 거예요.

## 2. 신호의 여행을 따라가 봐요

<SectionClip src={clipBase + "/ep02.mp4"} title="67화 — 신호의 여섯 걸음 여행" />

버튼 한 번에 일어나는 일을 순서대로 따라가면, 배운 것들이 전부 연결됩니다.

1. 스마트폰 브라우저가 Wi-Fi로 **요청**을 보내요: "/on 주세요."
2. 공유기가 요청을 **라즈베리파이의 IP 주소**로 전달해요.
3. Flask가 요청을 받고, 메뉴판에서 /on 담당인 **turn_on 함수**를 실행해요.
4. 함수 안의 `led.on()`이 **GPIO17을 3.3V로** 바꿔요.
5. 전류가 저항과 LED를 지나 GND로 흐르고, **불이 켜져요.**
6. 함수가 돌려준 "LED를 켰어요"가 **응답**으로 폰 화면에 나타나요.

무선 신호에서 전자 회로까지, 여섯 단계가 1초도 안 되는 사이에 일어나요.
이 경로의 모든 조각을 여러분이 직접 만들었다는 것이 오늘의 자랑거리입니다.

<Callout type="analogy">

**이것이 사물인터넷(IoT)이에요.**

IoT는 "사물(Things)이 인터넷에 연결된다"는 뜻이에요.
스마트 전구, 로봇청소기, 스마트 플러그의 공통 구조는 오늘 만든 것과 같습니다.
**명령을 보내는 기기(폰) → 네트워크 → 사물에 붙은 작은 컴퓨터 → 실제 장치.**
우리 교실의 LED가 상용 제품에서는 전구와 모터로 바뀔 뿐이에요.

</Callout>

## 3. 주소창 말고 진짜 버튼 만들기

<SectionClip src={clipBase + "/ep03.mp4"} title="68화 — 주소창 말고 진짜 버튼" />

주소를 직접 입력하는 리모컨은 불편하죠.
응답으로 글자 대신 **HTML**을 보내면 버튼이 있는 페이지를 만들 수 있어요.

```python
@app.route("/")
def home():
    return """
    <h1>우리 집 스마트 조명</h1>
    <p><a href="/on">켜기</a></p>
    <p><a href="/off">끄기</a></p>
    """
```

HTML은 웹페이지의 생김새를 적는 약속이에요.
`<a href="/on">`은 누르면 /on 주소로 요청을 보내는 **링크 버튼**을 만들어요.
이제 첫 화면에서 켜기와 끄기를 누르기만 하면 됩니다.
실습에서는 여기에 현재 상태 표시까지 붙여 제대로 된 조명 페이지를 완성해 봐요.

<Callout type="important">

**우리 서버는 아직 아무나 조작할 수 있어요.**

지금 만든 서버에는 **비밀번호가 없어서**, 같은 Wi-Fi의 누구든 주소만 알면 LED를 조작할 수 있어요.
교실 실습에서는 괜찮지만, 진짜 집의 장치라면 큰 문제겠죠.
실제 IoT 제품에는 로그인, 암호화 같은 **보안 장치**가 반드시 들어갑니다.
"동작하는 것"과 "안전한 것"은 다른 문제라는 걸 기억해 두세요.
우리 실습 서버도 수업이 끝나면 꺼 둡니다.

</Callout>

<details>
<summary>2. 웹으로 제어하는 방식과 지난 시간의 BLE 방식은 무엇이 비슷하고 무엇이 다른가요?</summary>

둘 다 무선 신호가 입력이 되어 프로그램의 판단을 거쳐 GPIO 출력으로 이어지는 구조예요.
다른 점은 연결 방법이에요. BLE는 블루투스로 가까운 거리에서 일대일로 연결하고,
웹 방식은 Wi-Fi 네트워크를 거쳐 브라우저만 있으면 어떤 기기든 접속할 수 있어요.

</details>

<details>
<summary>3. 지금 만든 스마트 조명 서버를 진짜 집에서 그대로 쓰면 위험한 이유는 무엇인가요?</summary>

비밀번호 같은 보안 장치가 없어서 같은 네트워크의 누구나 조작할 수 있기 때문이에요.
실제 제품에는 로그인과 암호화 같은 보안이 반드시 필요합니다.

</details>
